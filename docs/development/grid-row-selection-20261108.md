# 网格本页反选与清空勾选

在 MySQL、MariaDB、PostgreSQL 和 SQLite 的表页或查询结果中，先勾选要排除的记录，再点「反选本页勾选」。当前网格中已勾选的行会取消勾选，其余可参与的行会勾上。无勾选时可用反选勾上当前范围，包含滚动区域之外已经载入的行。点「清空本页勾选」可一次取消全部勾选。

表页范围以当前载入的页为准，反选跳过待删除草稿。查询结果范围以当前显示的已载入结果为准。两项操作沿用网格原勾选状态，保留活动数据格和草稿。复制、导出及批量编辑继续使用各自原有的准入和确认流程。

## 验证

- macOS arm64 的 Node.js 24.17.0 运行时检查、类型检查和构建通过，12 个相关单测文件共 175 项通过。受限环境中的首轮 Electron 测试未能启动，改用授权的本机窗口运行。
- SQLite 与查询结果 4 项真实窗口测试通过。查询结果按倒序复制反选范围，覆盖尚未渲染的行。SQLite 可编辑表保留原存储类型，包含当前页末行。只读视图验证了反选及清空，操作期间没有新增数据任务。
- Server-200 隔离 PostgreSQL 18.6 的真实窗口验证通过。翻至第二页后，反选跳过一条待删除草稿和一条已勾选记录，共勾选 58 条。跳到第 60 行验证末行已选中，随后清空并核对实库仍有 140 行。隔离容器及转发已清理。
- PostgreSQL 整套工作区回归在 120 秒、零重试门槛下单轮通过，约 115 秒，记录 79 项观察。临时配置已移除，独立核对实库后清理隔离容器。
- Server-200 的 MySQL 5.7、8.0 与 MariaDB 10.11、11.4 四条专用基线均通过。各随机库反选后进入原批量表单，预览与提交按预期只影响目标两条记录。窗口正常退出，随机库已精确清理。

MySQL 8.4 专用容器在测试前已停止，预检阶段未创建随机库。WIN11-TEST 会话未连通，Windows、安装包以及网络数据库查询页的反选专项另验。跨页统一勾选仍为后续工作。
