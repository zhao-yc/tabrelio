# MySQL／MariaDB 自定义键与字段映射同步

MySQL 和 MariaDB 的 InnoDB 表可以按异名字段和联合业务键同步。单表可勾选具体差异，多表可在同一个右侧数据库中混用默认规则和自定义映射。两种引擎可互为来源和目标。业务键在两侧必须非空且唯一，目标表可以没有主键或唯一业务键索引。

## 操作

1. 在「比较 MySQL／MariaDB 表数据」选定左右表，在「自定义匹配键与字段」添加对应字段，至少勾选一对匹配键。
2. 单表执行无筛选的完整比较，再勾选要同步的差异。多表逐对设置字段，选择需要同步的操作。默认选中插入和更新，删除需主动勾选。
3. 核对右侧目标、记录键和数量，输入准确的确认文字后提交。

更新只对发生变化的映射非键列赋值。插入只为映射列赋值，其余列使用右侧默认值、约束和自动计算规则。删除会移除右侧整行。生成列可以由右侧自动计算，映射目标需使用支持无损写入的普通列。

## 事务范围

预览在比较快照内保留完整右侧旧值。提交在同一个右侧 InnoDB 事务内复核目录、原行以及业务键行数，未映射列发生并发修改也会拦截。自定义键使用可重复读的锁定扫描，锁定目标记录和扫描间隙，防止没有唯一索引时并发插入重复键。旧服务器若开启禁用间隙锁的设置，会拒绝此类写入。[MySQL 锁定读](https://dev.mysql.com/doc/refman/8.4/en/innodb-locks-set.html) · [MariaDB InnoDB 锁](https://mariadb.com/docs/server/server-usage/storage-engines/innodb/innodb-lock-modes)

沿用每侧 10,000 行、8 MiB 读取上限和每批 100 行、1 MiB 的所选差异预算，以及触发器和入向外键保护。写后再核对映射值与业务键行数。任一表的约束错误或回读不一致都会中止整批提交。

原生验收的两端隔离库需在第二个测试数据库加载[映射同步夹具](../../tests/integration/fixtures/mysql-mapped-data-sync.sql)。

## 验证

2026-11-08 在 macOS arm64 通过 Node.js 24.17.0 运行时检查、严格类型检查、构建、59 项相关单测和 4 项 Electron 窗口测试。MySQL 8.4.11 与 MariaDB 11.4.13 实库验证异名联合键、无符号 64 位整数和二进制字段，区分不区分大小写排序规则下的不同键原值。并发修改未映射列与预览后出现的重复业务键均被拦截。第二张表的唯一约束失败后，第一张表的写入也回滚。

向 MariaDB 提交两表六项变更，再向 MySQL 反向提交两表两项更新。两端分别实测锁住无主键目标后，其他连接插入新键收到锁等待超时。独立查询确认现有行保留未映射字段，新增行使用目标默认值。

PostgreSQL 18.6 和 SQLite 的比较与同步通过回归。网络实库使用 Server-200 隔离容器，验收后已清理。Windows 测试会话未连通，Windows 和安装包待验。
