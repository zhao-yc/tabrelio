# PostgreSQL 估算执行计划

在 PostgreSQL 查询标签点击「查看估算计划」。选中单条 SQL 时预览选区，未选中时按光标位置选择语句。树形计划、原始 JSON 和计划结果表格可在同一个结果区切换，节点详情保留估计输出行数、成本、索引、过滤条件及原始 JSON 路径。

- 使用原物理会话，因此能规划该会话的临时表、角色和搜索路径。请求明确使用 `ANALYZE FALSE`，估算 `UPDATE`、`DELETE` 等语句时数据库不会运行原 DML。计划仍遵守 PostgreSQL 的锁及事务规则，规划错误可能使打开的事务进入失败状态。[PostgreSQL EXPLAIN](https://www.postgresql.org/docs/18/sql-explain.html)
- PostgreSQL 16 及以上的带位置参数语句使用通用计划。原 SQL 先由服务器 Parse 校验单语句，随后不绑定参数值读取计划。类型推断不足时可在 SQL 中加显式类型转换。[通用计划及参数示例](https://www.postgresql.org/docs/16/sql-explain.html)
- 读取期间可以通过查询标签的停止按钮取消。计划和视图切换不写入 SQL 执行历史。结构化显示最多 300 节点，原始输出按字节限额接收，超限时显示提示。

当前图形入口提供估算计划，实际执行分析、计划快照文件及比较继续推进。

## 验证

- Mac 类型检查、源码构建和 90 项定向单元通过，覆盖 PostgreSQL 词法、计划树精度、光标协议、原有计划界面及 SQLite 会话。
- Mac 完整单元回归覆盖 1,318 个测试文件，27,401 项通过，10 项 Windows 系统 tar 检查按平台跳过。
- Server-200 的 PostgreSQL 18 独占实库回归 5 项通过。服务器 Parse 拒绝附带第二条命令，通用计划保留 `$1`，预览写语句后原行保持，事务内临时表可规划，锁等待可取消。成功容器复核原行和零连接后清理。
- Mac 原生 Electron 窗口复验通过。真实操作覆盖光标所在语句、明确选区、节点成本和原始 JSON。计划区调整后根节点和总成本同时可见，前后语句与执行历史保持。单 worker、120 秒、零重试、trace 关闭，窗口退出及临时配置目录已复核。
- 初期实库发现扩展协议要求绑定参数槽，而空值试验改变了计划。最终实现先核对同会话的 Parse 确认，再无值获取通用计划，失败原件保留。
- 首次完整回归发现通用计划命令的光标字段破坏了旧契约。PostgreSQL 改用专用命令，旧计划入口继续严格拒绝光标字段。
- WIN11-TEST 会话不可达，本轮未派发，按约定在 Mac 验证。Windows 原生窗口和安装包尚待验收。

## 小窗口中的计划树

查询工作台按计划工具栏、帮助和诊断提示的实际占用为树与节点详情留出空间。新计划出现时，如果结果在视区外，标签会滚动到结果。仍可向上滚动回到 SQL 编辑器，已保存的分栏偏好会在切回普通结果时继续生效。

2026-11-08 在 macOS arm64 通过运行时检查、类型检查、构建和 100 项相关单测。Server-200 隔离 PostgreSQL 18.6 的真实最小窗口专项通过。1024×680 窗口内，父子节点和所选节点总成本均达到 80% 可见门槛。编辑区保留 130 像素，读回原分栏偏好仍为 300 像素。独立连接确认原表记录保持，应用历史接口确认估算未新增执行记录。

基线中根节点仅约 19% 可见。首次调整后成本仍被裁切，随后补足计划区并保留编辑区最小高度。另一次复测通过界面断言后因测试夹具未启用退出确认而失败，补齐夹具后全例通过，隔离库和转发已清理。

原 PostgreSQL 工作区整套回归单轮通过，记录 79 项观察。原树节点及成本可见门槛、120 秒超时和零重试均保持。最终正常退出，临时配置目录已移除，独立核对原表和零连接后清理容器。单测中原先拒绝通用计划入口接收光标的断言已与现有契约同步，两种入口仍各自拒绝越界偏移和多余字段。Windows 会话未连通，Windows、安装包及其他驱动的原生布局待验。
