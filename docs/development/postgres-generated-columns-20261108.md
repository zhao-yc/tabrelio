# PostgreSQL 生成列

在「新建 PostgreSQL 表」或「查看结构 → 编辑字段 → 新增字段」，选好字段类型，再选择「生成方式」。表达式可以引用本行普通字段，例如 `"数量" * "单价"`。保存前预览 SQL。新增存储生成列时，PostgreSQL 会计算已有行，可能重写并锁定表。

| 操作 | PostgreSQL 版本 | 行为 |
| --- | --- | --- |
| 新增存储生成列 | 12+ | 写入记录时计算并保存结果 |
| 新增虚拟生成列 | 18+ | 读取时计算结果 |
| 修改生成表达式 | 17+ | 按原生成方式应用新表达式，存储列会重算已有值 |
| 存储生成列转为普通列 | 13+ | 保留已有值，之后按普通字段写入 |

修改时选择「编辑生成列」和原字段。客户端会载入目录中的当前表达式。修改表达式或选择「转为普通列」后，点击「加入改动」，再预览并确认。已有表编辑沿用可管理的普通表范围。

表达式不能与标识属性或普通默认值并用。预览检查文本边界和 SQL 语法，提交时由 PostgreSQL 校验字段引用、类型和函数不可变性。虚拟列仅能使用内置类型和函数。需要引用用户 schema 中的存储列表达式函数时，请使用 schema 限定名。任一项失败时整批回滚，提交前核对目录中的生成方式和表达式是否存在。[生成列](https://www.postgresql.org/docs/18/ddl-generated-columns.html) · [ALTER TABLE](https://www.postgresql.org/docs/18/sql-altertable.html)

## 验证

- macOS arm64 的 Node.js 24.17.0 通过原生运行时门槛、类型检查、构建和 87 项相关单元测试。
- Server-200 隔离 PostgreSQL 18.6 通过 14 项 Electron 源码用例及 3 项实库集成用例。独立连接核对建表、新增虚拟列、两种生成列修改表达式，以及存储生成列保值转为普通列。语法错误在预览拒绝，违反不可变性要求的改动使同批前序重命名回滚。
- 首轮原生用例无法按可访问名称定位预填表达式的文本框。补充显式名称后沿用原断言复验，两轮隔离资源均在零客户连接后清理。
- WIN11-TEST 不可达，本轮未派发。Windows 原生窗口、安装包及较低版本 PostgreSQL 待验。
