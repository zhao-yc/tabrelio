# PostgreSQL 空间分析

在连接树右键点击 PostgreSQL 数据库，选择「PostgreSQL 空间分析」。报告列出当前角色可见的物理表、子分区及物化视图，可按 Schema、关系名称和关系类型筛选，按空间、估算行数或名称排序。每页 50 条，顶部汇总覆盖当前筛选的全部结果。展开「按 Schema 汇总」可查看并切换到相应 Schema。

表数据空间包含 TOAST、空闲空间映射和可见性映射，索引空间单独计入。分区父表没有单独的物理数据，子分区按各自占用计入，父表名称按可见权限展示。点击「查看明细」可核对十进制字节数、行数估算、表的顺序扫描次数，以及每个索引的大小、扫描次数和状态。[PostgreSQL 空间函数](https://www.postgresql.org/docs/18/functions-admin.html#FUNCTIONS-ADMIN-DBOBJECT) · [PostgreSQL 统计视图](https://www.postgresql.org/docs/18/monitoring-stats.html)

读取使用独立只读会话。大小是本次读取时的值，行数来自统计估算，翻页会重新读取目录。单次筛选范围最多 4,000 个物理关系。范围更大时可缩小筛选。明细绑定原数据库和关系身份，同名替换后需要刷新报告。

## 验证

- macOS arm64 的 Node.js 与 SQLite 原生运行时检查、类型检查、构建及 146 项相关单测通过。
- Server-200 隔离 PostgreSQL 18.6 的 34 项 Electron 用例通过。独立 SQL 核对 53 个物理关系、跨两页汇总的精确字节、索引明细和 1,200 行统计估算。验证子分区单独计量、父表标签按权限显示及同名替换后拒绝打开旧明细。
- 4 项实库集成回归通过。两轮隔离测试均在客户连接归零后关闭隧道并清理容器。
- 首轮测试在统计收集器尚未发布更新时读到零。将分析移到数据事务提交后，并确认共享统计已更新，再复验界面显示。
- WIN11-TEST 不可达，本轮使用 macOS arm64。Windows 原生窗口、安装包和其他 PostgreSQL 版本待验。
