# MySQL 和 MariaDB 原主键查询复制

在有主键的 MySQL 或 MariaDB 表页，打开「更多 → 生成查询 → 复制原主键查询 SQL」。有勾选时使用本页勾选行，否则使用当前数据格所在行。复制得到完整的 `SELECT` 普通文本，可粘贴到查询编辑器核对。

复合主键按目录顺序组合每条记录，再用 `OR` 连接。主键取已载入的原值，本地草稿修改不会替换条件。精确整数、小数和 BIT 保持原精度。文本和二进制使用十六进制字面量，文本沿用主键的比较规则。TIMESTAMP 主键使用读取时取得的 Unix 时间，便于在不同时区的会话复用。

只使用本页已核对的目录和原始行。未载入所需主键、缺失时间原值、包含近似数值主键、选中本地新增行或超过生成预算时，整批拒绝。视图和无主键表没有入口。

## 验证

- macOS arm64 运行时检查、严格类型检查、构建和 403 项定向单测通过。覆盖原值及目录绑定、缺失时刻拒绝、普通页不签发补取租约，以及附带时刻超出预算时回退普通浏览。
- 最终构建的两项 macOS Electron 用例通过，连接 Server-200 上的隔离 MySQL 8.4.11 和 MariaDB 11.4.13。独立连接在 +09:00 和 `NO_BACKSLASH_ESCAPES,ANSI_QUOTES` 会话中执行复制事件的原始 SQL，核对相邻 UINT64、BIT64、Latin1 文本、二进制与微秒 TIMESTAMP。返回记录与当前行或勾选范围一致。
- 前两次 MySQL 用例发现普通页提前返回导致缺少原时刻，修正后复验通过。失败日志和原窗口保留，所有本轮隔离容器、匿名卷和回环转发已清理。

WIN11-TEST 无法连接。本轮拦截复制事件核对 SQL 原文，Windows、安装包和系统剪贴板写入待验。
