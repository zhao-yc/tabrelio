# 在已有 MySQL 或 MariaDB 库中恢复缺失表

在「打开数据库备份归档」选择第三版指定表 ZIP 和现有目标库，点击「检查目标」。当目录可见性已确认，且归档中的表名和触发器名在目标库中可用时，可以恢复结构或结构及数据，同时保留库中的无关对象。同名表、视图、其他表类对象或触发器会阻止恢复。仅恢复数据仍要求所选同名 InnoDB 表可见。第一版和第二版整库归档仍要求同名空库或新库。

恢复前会在执行连接上重新核对归档、当前数据库和名称冲突。已有对象的目标库若启用了表名大小写折叠，选中的非 ASCII 表名会保守拦截。折叠后重复的归档表名也会拦截。触发器按目标目录的比较规则判断，可能拦截目录视为等价的拼写。 [MySQL 标识符大小写规则](https://dev.mysql.com/doc/refman/8.4/en/identifier-case-sensitivity.html) · [MariaDB 标识符大小写规则](https://mariadb.com/docs/server/reference/sql-structure/sql-language-structure/identifier-case-sensitivity)

请使用可信归档，并在恢复期间暂停目标库的 DDL。预检检查目录名称，外键依赖、约束名称、DEFINER 和执行权限仍需核对。检查和回放之间的并发 DDL、回放中的错误或取消均可能导致部分 DDL 或已提交的数据保留。
