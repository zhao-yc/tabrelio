# MySQL／MariaDB 多表事务同步

在多表比较窗口，可把 MySQL 或 MariaDB 的多对表差异同步到同一个右侧数据库。两侧可以选择不同连接、数据库或引擎，每张右侧表只能出现一次。

## 操作

1. 在「比较 MySQL／MariaDB 表数据」选定两侧连接与数据库，打开「多表比较」，添加至少两对表。各表对可沿用默认规则，也可使用[自定义键与字段映射](mysql-mapped-data-sync-20261108.md)。
2. 在「MySQL／MariaDB 多表同步」选择操作。默认选中插入和更新。需要移除仅存在于右侧的记录时，勾选删除。
3. 点击「预览多表同步」，检查每张右侧表、操作和记录键。读取期间可取消，生成后可放弃预览。
4. 输入窗口显示的目标确认文字，点击「确认多表同步」。检查事务回执后按需重新比较。

## 事务范围

每批最多 32 对 InnoDB 表，所选差异累计最多 100 行及 1 MiB。各表对分别读取快照，提交使用预览时的来源值。目标需满足[单表同步](mysql-data-sync-20261107.md)的结构、列类型和权限条件。启用触发器的表会拦截。涉及更新或删除时也会核对入向外键。

程序在同一个右侧会话中按表名顺序加锁，先复核全部目标结构和待更新、删除的原行，再执行变更。逐条核对影响行数和回读结果，最后提交一次。任一写入失败会回滚同一事务中的全部行变更。显式插入标识值可能推进右侧自增计数。提交结果未知时须核对右侧数据库，程序不会自动重放。

## 验证

2026-11-08 在 macOS arm64 通过 Node.js 24.17.0 运行时检查、严格类型检查、构建、52 项相关单测及 4 项 Electron 窗口测试。MySQL 8.4.11 与 MariaDB 11.4.13 实库核验默认不删除、精确目标确认、第二张表唯一键冲突后的整批回滚，以及预览后右侧原值变化时拦截。显式选中删除后向 MariaDB 提交两表五项变更，再换向向 MySQL 提交两表两项变更，分别独立读回两侧结果。PostgreSQL 18.6 和 SQLite 的数据比较与多表同步通过回归。

网络实库使用 Server-200 隔离容器，验收后已清理。Windows 测试会话未连通，Windows 和安装包待验。
