# SQLite 表页复制 INSERT SQL

在 SQLite 普通表里选中一个数据格后点击「复制当前行为 INSERT SQL」，或勾选多行后点击「复制选中行为 INSERT SQL」。多行按原页顺序输出，翻页后需要重新选择。以只读连接打开的普通表也可复制。视图、虚拟表、影子表和内部表不提供入口。

SQL 沿用 `main`、原表名及实际列名。布局隐藏列仍包括在内，生成列交给目标表重算。原页标记决定每格是整数、实数、文本、BLOB 还是 NULL。数字外观的文本保留为文本，含 NUL 的文本可跨数据库编码回放。只复制可核对的已载入原值。所选行含新增、修改或删除草稿，或超出行数、单元格及字节上限时，整次拒绝。

复制只生成普通文本。执行前请核对目标表结构、约束、触发器和主键是否冲突。SQLite 隐式 rowid 未作为普通字段读取时，目标库会为新行分配自己的 rowid。

## 验证

- macOS arm64 的运行时检查、严格类型检查、构建和 353 项定向单测通过。扩展测试首轮 5,463 项通过，另外 70 项在未改动的 `1000d47a` 上按同名用例复现，涉及 VM 测试桩缺少 `appModalSelector`、`checkedExport` 或 `renderedEditor`。本轮修补了直接相关的结果 SQL 取消测试桩，保留了取消和文件原子性断言。
- SQLite 原生复制用例验证当前行、勾选行、只读连接、草稿拒绝及翻页失效。从复制事件取出的文本原样回放到另一编码的隔离 SQLite 库，直接回读核对 64 位整数、同形的 REAL 和 TEXT、空 BLOB、生成列以及 NUL 后的 Unicode。
- 三项 SQLite 原生回归和两项 PostgreSQL 18.6 实库窗口回归通过。旧 SQLite 剪贴板用例的首轮失败来自放弃草稿提示文字，改用实际工作区文案后通过，首轮日志与独占窗口保留。PostgreSQL 隔离容器、匿名卷和回环转发已清理。

WIN11-TEST 无法连接。原生用例拦截本例复制事件，Windows、安装包和系统剪贴板写入待验。
