# SQLite 多表事务同步

SQLite 多表比较窗口可对同一个右侧数据库文件的多张表一次性提交差异。可使用两个文件，也可在同一个文件中使用彼此不重叠的来源表和目标表。

## 操作

1. 从「工具 → 比较 SQLite 表数据」选择左右连接，打开「多表比较」，添加至少两对表。使用默认主键和完整字段规则。
2. 在「SQLite 多表同步」选择操作。默认选择插入和更新。若要删除仅存在于右侧的行，主动勾选「删除」。
3. 点「预览多表同步」。程序重新读取各表，列出所选操作覆盖的目标表、数量和记录键。可停止预览或放弃已生成的预览。
4. 输入窗口显示的确认文字后，点「确认多表同步」。检查实际事务回执，再按需重新比较。

## 事务范围

每批最多 32 对表、100 行和 1 MiB 的所选差异。提交会锁定原右侧文件，写入前核对每张目标表的目录及关联限制，逐行核对右侧原值，写后复核所有受影响的行。任一表发生结构变化、原值冲突或约束错误，都不会提交部分表。右侧表含触发器、被外键引用或含生成列时，沿用现有同步限制。

预览只读，各表对的来源快照分别读取。提交只使用预览时读到的来源值。任务记录保留实际右侧表名、请求行数、已处理行数和提交或回滚确认。未知结果需核对原文件，程序不会自动重放。网络数据库多表事务和自定义字段映射写入待实现。

## 验证

2026-11-08 在 macOS arm64 通过运行时检查、严格类型检查、源码构建和 107 项相关单测。两项 Electron 原生窗口测试通过，覆盖新多表事务及原单表同步回归。独立 SQLite 读回确认，第二张表在预览后出现原值冲突时，第一张表已处理的两行全部回滚。触发器检查在首条 DML 前拦截。最终同一事务提交两表四项变更，来源文件的数据保持原值。任务回执保留两张目标表及实际提交或回滚状态。

Windows 测试会话未连通，Windows 和安装包待验。本轮原生测试使用隔离 SQLite 文件。
