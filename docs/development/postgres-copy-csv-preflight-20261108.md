# PostgreSQL 原生 CSV 整文件检查

在已有表的「导入数据」中选择「PostgreSQL 原生 CSV」、分隔符和记录范围，再选择一个文件。点击「检查整个 CSV 文件」后，仍可核对原列映射。检查期间可以取消。

检查按逻辑记录读取本地文件，核对 UTF-8、引号边界、所选数据的列数和行尾。引号内换行属于同一记录。能定位的错误会显示记录号，有表头时表头也计入记录号。为了兼容较早的 PostgreSQL 版本，单独一行的未加引号的反斜线加句点会被拦截，作为实际字段值时应加双引号。[PostgreSQL COPY 的 CSV 规则](https://www.postgresql.org/docs/18/sql-copy.html)

检查失败后需要修正并重新选择文件。检查通过会显示所选数据记录数，正式导入前仍须确认列映射和点击导入。实际 COPY 使用检查过的原字节范围，提交前再次核对文件版本和服务器行数。字段类型、权限、触发器和约束由 PostgreSQL 在导入事务中处理。

整文件检查为可选步骤。原生 CSV 多文件导入已经在选文件时完整检查文件，tabrelio CSV、TXT、JSON、XML 和 Excel 继续沿用各自的读取流程。

## 验收记录

- 2026-11-08，macOS arm64 通过运行时检查、严格类型检查、构建及 93 项相关单测。单测覆盖有引号的换行、记录范围、坏编码、列数、混合行尾、结束标记、文件变化、检查取消和退出收尾。首轮本地测试发现二进制解析的错误记录分支及退出夹具缺少新增状态，修正后复测通过，原报告保留。
- Server-200 隔离 PostgreSQL 18.6 通过 3 项 Electron 源码用例与 1 项表页实库集成回归。第 8 条多列记录在导入前被拦截。原文件通过检查后修改内容，提交仍被拒绝。两种情况均由独立连接核对目标表和默认值序列未变。
- 重新选择并确认导入后，实库核对三行的精确整数、NULL、空字符串和引号内换行。多文件原生 CSV 与其他格式及多工作簿继续通过回归。隔离容器、转发与数据库会话已核对清理。
- WIN11-TEST 不可达，本轮使用 macOS 源码。Windows、安装包、其他 PostgreSQL 版本、应用内 SSH／TLS 及原生界面取消操作待验。
