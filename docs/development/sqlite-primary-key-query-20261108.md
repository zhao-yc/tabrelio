# SQLite 原主键查询复制

在有主键的 SQLite 普通表中，点击「复制原主键查询 SQL」。有勾选时使用本页勾选行，否则使用当前数据格所在行。只读连接打开的普通表也可使用。生成的完整 `SELECT` 使用 `main` 中的原表，复制本身只写普通文本。

复合主键按实际索引顺序组合每条记录，再将各条条件用 `OR` 连接。SQLite 使用主键索引的 BINARY、NOCASE 或 RTRIM 排序规则比较，字段声明的排序规则可能不同。主键值沿原页的实际存储类型生成。隐藏主键列仍包含在内，已有记录的本地草稿仍使用已载入的原键。

SQLite 的部分普通表允许主键字段为 NULL，且多条记录可能拥有相同的空键组合。所选行含 NULL 主键、只存在本地新增草稿或超过生成预算时，整次拒绝复制。长条件分组生成，可在 SQLite 默认表达式深度内执行 1,000 行的查询。无主键表和视图没有入口。

## 验证

- macOS arm64 运行时、严格类型检查、构建及 5,538 项扩展单测通过。实库单测执行 1,000 条主键条件，准确返回所选记录。
- SQLite 原生专项使用独立连接执行复制事件中的原文，核对大小写相似键、复合键交叉项、64 位整数、二进制、空键拒绝、草稿原值和只读连接。首轮观察端默认将整数读为 JavaScript Number，启用 BigInt 后通过，原日志和隔离窗口保留。
- 最终构建的 7 项 macOS Electron 用例通过，其中 SQLite 4 项、隔离 PostgreSQL 18.6 回归 3 项。隔离 PostgreSQL 容器、回环转发和匿名卷已清理。

WIN11-TEST 无法连接。本轮拦截应用复制事件读取 SQL 原文，Windows、安装包和系统剪贴板写入待验。
