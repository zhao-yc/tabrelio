# 数据比较方案与左右互换

SQLite、PostgreSQL、MySQL 和 MariaDB 的表数据比较支持命名方案和左右互换。对应 Navicat 数据同步中的保存配置与交换源目标步骤。[Navicat 16 官方手册 Data Synchronization](https://www.navicat.com/manual/pdf_manual/en/navicat_16/win_manual/navicat_en.pdf#page=180)

## 使用

1. 从「工具」打开对应的表数据比较窗口，选定左右连接和表。需要筛选时填写两侧共用的条件。
2. 展开「比较方案」，填写名称后点「另存为新方案」。已有方案可选择载入、更新、改名或删除。
3. 点「应用方案」恢复左右表和筛选，或点「交换左侧与右侧」保留筛选并调换方向。两项操作都会清空已有结果、页码、差异勾选和确认信息。核对两侧后点「比较数据」。
4. 对完整比较中允许写入的右侧表，可重新勾选、预览并确认同步。同步预览打开时，先返回差异列表再载入或交换。筛选比较只读。

## 保存范围

方案保存在当前设备的应用配置库。SQLite 和 PostgreSQL 分开列出，MySQL 和 MariaDB 共用方案列表，可保存两种连接互相比较的配置。每组最多 32 项，保存左右对象标识及筛选值，SQLite 保留筛选的原类型和文本精度。筛选值以原文保存在本机。方案字段排除连接凭据、运行快照、差异结果和同步确认。

连接改名后可以继续载入。连接缺失、缺少所需文件配置或连接路由配置改变时，载入会提示重新选择或核对。重新选定两侧后，可以更新原方案。实际表和写入条件在发起比较或同步时由对应数据库流程核验。

## 验证

2026-11-08 在 macOS arm64 通过运行时检查、严格类型检查、源码构建及 25 项相关单测。单测覆盖本机配置重开、SQLite 整数精度、路由变化、旧修订冲突、写盘失败恢复和 IPC 校验。

四项源码 Electron 原生窗口测试通过。SQLite 跨文件用例验证方案重载、精确筛选、左右原值对调和后续同步。PostgreSQL 18.6 验证跨库、跨连接方案及原比较和同步流程。MySQL 8.4.11 与 MariaDB 11.4.13 验证跨引擎方案、换向后重选差异、预览期间的操作限制及两种方向的实际同步。网络数据库使用 Server-200 上的隔离容器，均已清理。第四项为 SQLite 查询导出方案及实际输出文件的回归。

Windows 测试主机未连通。Windows、安装包和其他实库版本待验。Navicat 的多表映射仍在功能清单中。
