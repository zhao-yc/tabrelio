# PostgreSQL 数据库管理

在连接树右键点击 PostgreSQL 连接，选择「管理 PostgreSQL 数据库」。窗口从维护库读取可见数据库的所有者、注释、编码、排序规则和连接设置。可在窗口中切换维护库，再点击「读取数据库目录」。

- 新建数据库时可选 `template1` 或 `template0`。前者使用服务器默认模板，后者从 PostgreSQL 的原始模板创建。所有者留空时使用当前角色，指定所有者时填写准确的现有角色名。
- 可编辑、清空数据库注释，或转移所有者。连接上限为 `-1` 时表示不限连接数。关闭「允许新连接」后 PostgreSQL 拒绝新连接，已有会话继续运行。
- 改名前先连接到另一个维护库，并关闭本工作台中引用原库名或目标名称的标签。PostgreSQL 要求目标库没有活动会话。窗口保护当前维护库、连接配置中的默认库和 `postgres`，这三个名称不能在此改名或关闭新连接。

预览只读取服务器目录。应用时重新核对维护库、原数据库或模板的身份、目标名称和权限。新建数据库通过单独会话发送并回读目录，已有库的变更在事务内执行并复核。收到结果待核对提示时，先刷新目录确认实际状态。[CREATE DATABASE](https://www.postgresql.org/docs/18/sql-createdatabase.html) · [ALTER DATABASE](https://www.postgresql.org/docs/18/sql-alterdatabase.html)

## 验证

- macOS arm64 的 Node.js 与 SQLite 原生运行时检查、类型检查、构建和 142 项相关单测通过。
- Server-200 隔离 PostgreSQL 18.6 上，24 项 Electron 用例通过。独立连接核对了两种模板建库、指定所有者、注释逐字回读、禁用后拒绝新连接、恢复连接、转移所有者，以及改名保留 OID 和表数据。同名替换被拒绝，提交令牌只消费一次。
- 4 项实库集成回归通过。两轮隔离测试均在客户连接归零后关闭隧道并清理容器。
- 首轮 Electron 用例将库名中的数字误作连接上限，提前读取目录。已改为等待上限及允许连接状态对应的单元格，复验通过。
- WIN11-TEST 不可达，本轮使用 macOS arm64。Windows 原生窗口、安装包及其他 PostgreSQL 版本待验。
