# TXT 文件导入

在 MySQL、MariaDB、PostgreSQL 或 SQLite 的可写表打开「导入数据」，或者在数据库节点打开「从文件导入新表」，再选择「TXT 文本」。

1. 选 UTF-8、UTF-16 LE 或 GB18030，按原文件选择记录换行，也可自动识别。
2. 对于分隔文本，选择 Tab、逗号、分号、竖线、空格，或输入 1 至 8 个字符的自定义分隔符。可用双引号或单引号包住包含分隔符和换行的值，在字段内把同一引号写两次。若原文件不使用引号，选择「无」。
3. 对于固定宽度文本，按列顺序填写逗号分隔的宽度，例如 `8,12,20`。宽度按 Unicode 码点计数，选中的记录须恰好等于宽度总和。每条记录最多 1,000 列，宽度总和最多 65,536。需要去除两端填充时，勾选「去除字段两端填充空格」，该选项仅移除 ASCII 空格。
4. 文件有字段名时，勾选「TXT 包含字段名记录」，并填写字段名记录号，默认第 1 条。字段名须非空且唯一。无表头时，从「第1列」开始按位置映射。数据默认从字段名之后或无表头文件的第 1 条开始，最后数据记录号留空则读到文件末尾。
5. 选择 `.txt` 文件，核对样本、源列、目标字段及字段类型。按界面提示预检并确认。新表流程先确认建表，之后再确认写入数据。

例如报表第 1 条是说明，第 2 条是字段名，第 3 条是注释，第 4 至 20 条是明细，第 21 条是汇总，依次将三个记录号设为 2、4、20。首末数据记录都包含在导入范围内。编号从 1 开始，空白记录计数，分隔文本限定符内的换行属于同一条记录。保存导入配置时可一并保存范围。

空字段保留为空字符串，`\N` 表示 NULL。以反斜线开头的普通文本用额外一个反斜线转义。映射到支持此语法的二进制列时，可用 `base64:` 前缀传入 Base64。范围外记录可有不同的列数或宽度，整个文件仍须符合选定编码和引号语法。已绑定源指纹的导入流程会核对原文件的全部字节。新表已创建而数据写入失败时，可在原表上重新配置导入。

MySQL 和 MariaDB 支持 InnoDB 的整批预检和按键处理。PostgreSQL 的普通表和分区表可直接追加，有合适的匹配键时也可按键处理。SQLite 使用现有的普通表预检与追加流程。

分隔文本、固定宽度布局和记录范围参考官方手册。[Navicat 导入向导](https://www.navicat.com/manual/online_manual/en/navicat_18/win_manual/import_wizard.html)
