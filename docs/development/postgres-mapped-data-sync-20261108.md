# PostgreSQL 自定义键与字段映射同步

PostgreSQL 可按异名字段及联合业务键同步单张普通表，也可在同一个右侧数据库的多表事务中混用默认规则与自定义映射。匹配键在两侧必须非空且唯一。右侧普通表可以没有主键或唯一索引。

## 操作

1. 在「比较 PostgreSQL 表数据」选择两侧连接、数据库及表，在「自定义匹配键与字段」添加对应字段，至少标记一对匹配键。
2. 单表同步先执行无筛选比较，再勾选要同步的差异。多表同步可逐表设置映射，然后选择整批操作。默认选择插入和更新，删除需主动勾选。
3. 预览目标和记录键，输入准确的确认文字，再提交到右侧。

更新保留目标匹配键及未映射字段。插入只为已映射的列赋值，其余列使用目标默认值及约束。删除会移除整行。普通生成列由数据库计算。显式插入标识键时，关联序列仍按原 PostgreSQL 行为处理。

## 事务范围

同步复用 100 行和 1 MiB 的所选差异预算，以及 PostgreSQL 单表的权限、触发器和入向外键检查。分区表、筛选结果及不支持无损写入的映射可继续用于比较。目标表锁覆盖键的行数核对和实际提交，原行版本也能识别未映射字段的并发改动。数值匹配键的小数尾零不产生更新差异。

程序逐条核对影响行数和映射值，提交前复核自定义键的实际行数。遇到重复键、并发冲突或约束错误时拒绝写入或整批回滚。提交回执未知时需核对右侧数据库。

## 验证

2026-11-08 在 macOS arm64 通过 Node.js 24.17.0 运行时检查、严格类型检查、构建、34 项相关单测和 4 项 Electron 窗口测试。PostgreSQL 18.6 实库确认无主键表的二进制字段更新、未映射列的并发修改拦截，以及联合键重复时在写入前拒绝。混用默认规则的两表事务验证第二张表的检查约束失败后整批回滚，最终成功提交两表四项变更。独立读回确认右侧保留未映射值和原键精度，新增行使用目标默认值及生成表达式。重新预览无待同步差异。

MySQL 8.4.11、MariaDB 11.4.13 和 SQLite 的比较与同步通过回归。网络实库使用 Server-200 隔离容器，验收后均已清理。Windows 测试会话未连通，Windows 和安装包待验。
